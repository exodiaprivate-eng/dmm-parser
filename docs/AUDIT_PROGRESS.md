# Field-level audit progress (IDA-driven)

Loop goal: confirm every Tier 1 typed table's Rust struct matches its
IDA reader function's wire layout AND uses canonical (snake-cased
Korean error string) field names.

Round-trip matrix already proved 121/122 tables produce byte-perfect
output on live 1.05.02. This audit adds field-name correctness on top.

When all 122 are audited, switch to BagSpace silent-fail trace.

## Audit method (per table)

1. `list_strings_filter` for `<TableName>의 _key를` to find the
   `_key` failure error string address.
2. `get_xrefs_to` that string → parent function (the per-record reader).
3. `decompile_function` of the reader.
4. Extract field-name list from error strings (one per `if` rung).
5. Compare to Rust struct field list (snake_case).
6. Mark PASS / MISMATCH; if mismatch, fix Rust source, re-run round-trip
   test for that table.

## Audit priority note

Mod authors target **top-level** table fields by name in v3 intents
(e.g., `default_slot_count` on `inventory_info`). Nested struct field
names (e.g., `CharacterInfoSubData.raw_a`) are accessed via dotted
paths and rarely targeted directly.

**Highest-impact remaining audit work**: scan TOP-LEVEL struct fields
in the High-priority tables for placeholders, fix those. Skip
nested-struct placeholders unless a tester reports a specific failed
field-resolve.

### Iteration 3 (2026-05-05) — BagSpace trace

**BagSpace mod analyzed**: format 1/2 byte-patch mod with signature
anchor `02000900000043686172616374657200` (the "Character" CString
record header). 10 changes targeting `gamedata/inventory.pabgb` at
offsets 3218 / 3220 / 4108 / 4736 / 5497 / 5499 / 5826 / 6045 / 6482 /
15142. Each change is 2-4 bytes (default-size + max-size pairs for
backpack / private / kuku pot / wardrobe / kuku cooler / collectibles
/ gatherables).

**Code path traced**:
1. parse_mod_file collects patches → file_patches map
2. file_patches → pabgb_patches list (since "gamedata/" prefix)
3. Signature search in flat_data → anchor base resolved at line 10678+
4. Anchor vs absolute scoring at line 10706+ → picks convention
5. Replace pass at line 10785+ → for each patch:
   - Check if already-patched (current == patched_bytes) → silent skip
   - Verify original bytes → if match, write patched bytes
   - If mismatch → falls through to context scan / error log
6. final_data → LZ4 compress → paz_data → overlay_files → dmmsa group

**Found**: the V1/V2 patch path had **NO per-patch success/skip
logging**. BagSpace's 10 patches could pass, fail, or already-skip
silently. Adding diagnostics:

- **`[V1V2_APPLY]`** — emitted per patch that successfully wrote bytes
  (orig matched, patched written). Shows exact mod, offset, before, after.
- **`[V1V2_ALREADY]`** — emitted per patch that hit the already-patched
  silent-skip branch. Tells us when body came in pre-modified (e.g.,
  prior mount round) and the V1/V2 path is a no-op.

Both edits applied to `commands.rs` lines 10906+ and 10810+. Compile
verified.

**Next iteration**: with diagnostics in place, ship a build for testers
running BagSpace. Their mount_log will pin which of three failure
modes hits:
1. signature not found in flat_data (`[SIGNATURE]` `NOT FOUND`)
2. patches all hit "already-patched" silent skip (`[V1V2_ALREADY]` ×N)
3. patches actually applied but overlay/PAPGT registration is wrong
   (`[V1V2_APPLY]` ×N visible but in-game still vanilla)
